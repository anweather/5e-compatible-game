# The chat over the Claude API, 2026-11-02

An evaluation (#59, J-064, backlog 27): the game's own tool loop over the Messages API, against the same prompts and strict check as Claude Code, behind one seam so the two are adapters. The game's default stays Claude Code on Haiku (J-066), nothing a player gets changes, and the picker stays later. Haiku's rows are the main ones, as that's what players get.

**The answer.** The loop passes everything Claude Code does: 24 of 24 on the fixed set on both models, 6 of 6 held-out, 3 of 3 scope. On Haiku it's faster and half the money: 4.8 s to the world against 8.4 s, and $0.0251 for 24 prompts against $0.06. On Opus it's no faster, and slower on the spell and the house, but it costs less than half. The cache holds across prompts and across a gap of 7 minutes. **Keep it as a real adapter, not the default,** for players with no Claude plan: what it needs before shipping is a place for a key and J-060's terms, not more engine. One finding is worth taking back now: putting `notes.md` in the first message saves a reply, and Claude Code's path could do that too.

**Setup.** `chat-api`, the runs at f3a053e plus the parsing fix in the commit after it. Claude Code 2.1.316 for what's compared. API version `2026-10-21`, `claude-haiku-5-5` and `claude-opus-5-5`, hidden batchmode Editor, one player. Thinking and effort left at each model's default (adaptive, medium), the same request on both. Haiku's runs came first, then Opus's.

**Spent: $1.14 of real money, on 10 runs and 5 single prompts, 71 in all.** That's the API's own prices on each reply's `usage`, kept in a file the loop checks before every request, not a figure from the console. It includes about $0.01 estimated by hand for two replies a parsing bug cut off before they were counted. Andrew's plan: nothing here. (The 16 plan prompts are in `chat-context-2026-11-02.md`, J-066.)

**Run it.** `tools/probe.sh chatprompts --harness api` spends nothing, on a stand-in. Real money needs `--real-claude true --budget <file> --model <id> --out <folder>`, with the key on the Editor's process, then `--replay`, `chat-strict`, `chat-check`, as ever.

## Opening tokens and the cache

| Each prompt's first request | Claude Code, Haiku | API, Haiku | API, Opus |
|---|---:|---:|---:|
| Opening tokens | 15,691 | 12,673 | 12,673 |
| Read from the cache | 14,054 | 12,587 to 12,675 | 12,587 to 12,675 |
| Written | 1,635 | 0 to 190 | 0 to 190 |

- **The prefix is 12,587 tokens:** the 35 game tools and `add_note`, the loop's prompt and `Instructions`, with nothing of Claude Code's. It's cached for an hour, at a mark on `Instructions`. A cold write is 12,665 tokens: $0.0025 on Haiku, $0.1013 on Opus. It happened once in all these runs on Opus, and on Haiku only in the two uncounted replies.
- **Hits really hold across prompts, though each message is a new loop.** After the first, every prompt's first request read the whole prefix. A repeat of the same prompt also reads its own tail: 12,669 with 0 written, on runs 2 and 3.
- **What's written is what's new:** the player's words and the notes, about 80 to 190 tokens, against Claude Code's 1,635, which holds `Instructions` and its own wrapping. Then each reply writes what it added. Written a prompt is 1,117 on Haiku against 4,286 on the same six prompts.
- **The tail's mark is 5 minutes and the prefix's an hour.** In a loop the next request starts within seconds, so the tail never needs longer, and it's the cheaper write. The prefix is 2× to write, which pays from 2 prompts an hour more than 5 minutes apart (**inferred** from the prices).
- **The hour was tested, once:** the same prompt twice, over 7 minutes apart: 12,587 read both times. The 5-minute mark expiring wasn't tested, and `--ttl 5m` is there for it, but it would need the entry gone first.
- **Tool order and bytes:** tools go in name order and nothing dated or random sits before the last mark.

## The seam, as built

- **`IChatHarness`** (`Chem.Mcp`): `Busy`, `Take`, `Send`, `Cancel`. `ClaudeChat` implements it, and only one thing in it changed: it takes the game's key out of the process it starts. `GameChat.Harness` holds it, Claude Code in play. Only the probe sets another.
- **`ApiLoop`** (core): MCP client, tool list, request, cache marks, stops, retries, cost. No HTTP and no key. It writes the same lines as stream-json, so `ChatRecorder`, `chat-strict`, `chat-check` and `chat-report` read it with one extra line, and its records alone carry `harness` and `tokens.costBasis` (`api-real`). A Claude Code record is byte for byte as it was, which a fixture holds.
- **`ApiChat` and `ApiWire`** (view): the thread, the watchdog, and raw HTTP. Raw because Unity's runtime can't take the C# SDK, as with the MCP one.
- **Nothing from the loop decides shared state.** It calls the same server, and a change goes out as a room command like any other.

**How tools are locked down.** The loop offers and runs only `ApiLoop.Allowed`, an explicit list of 35 by name, which a test holds to the server's list today. A tool the server adds later stays out until someone reads it and names it. A name outside the list gets an error result and never reaches the server: tested, and on the stand-in `Bash` was turned away for real. The definitions are the server's text unchanged, with `inputSchema` renamed and `annotations` dropped. `eager_input_streaming` is off to leave them unchanged, as inputs here are small. `save` keeps the server's rule.

**Notes: what I chose.** The loop reads `notes.md` (its newest 60 lines) into the first message, and offers `add_note`, which takes one string, flattens it to one line, cuts it at 300 characters and appends it to that one file. There's no path to give and no read tool. A model can fill the notes with nonsense, up to the 60 lines kept, and nothing else. It saved a reply too: Claude Code's 9 failed `Read`s of 16 have no equivalent here.

**The key.** `ApiWire` reads it from the process's environment for each request and sends it as a header, nothing else. A failure's text is cleaned of it, and a refused key gives its own sentence, not one that opens the sign-in page. It was set only on the Editor I started, and removed from the shell after. With the Editor holding it, a stand-in reports that the claude process had neither key: `claude_is_handed_no_key`. A player's own `ANTHROPIC_API_KEY` is left alone, as it is today, so the Claude path doesn't change. A search of every record, stream and log for the key's value found nothing.

**The budget.** Checked before each prompt and each request, with the running total in a file. No file, or one that can't be read, means nothing starts. It stops at $9, and never came near.

## What's handled

| Case | What the loop does | Proved by |
|---|---|---|
| 429, 529, 5xx, a cut connection | Up to 4 tries, `Retry-After` if given (at most 30 s), else 1, 2, 4 s | Tests. Never met for real |
| Overloaded in mid-stream | The same, and the tokens already reported count | Test |
| 400, 401, 402, 403, 404 | Stops at once, in a sentence | Tests; a real 400 |
| `max_tokens` or `refusal` | Runs none of that reply's tools, and fails plainly | Tests |
| `pause_turn` | Sends the request again | Not tested: no server tools here |
| Turn cap, 16 | Fails plainly | Test. The most used was 9 replies |
| 240 s a prompt, and cancel | Stops the stream, ends as timed out or stopped | A test of a cancel before it starts. Not tried mid-stream, or on a real run |
| A model with no price | Refused, as the money couldn't be counted | Test |

**Not handled.** A context limit, as one message's loop stays small. Mid-stream cancel of a tool already running: it finishes, and an `apply` that went out stays. Server-side `fallbacks`: off, so each number is the model named, which means a refused Opus prompt simply fails. Haiku has none anyway. A reply's words reaching the box as they stream.

## What Claude Code gives that the loop doesn't

- **Sign-in and a plan.** A plan player pays nothing per prompt and has no key to mind. The loop needs a key, a place to keep it, and a way for a player to get one. That's the real cost of this path, and none of it exists: an environment variable won't do for a player.
- **Limits it can read.** Claude Code's stream says how much of the five-hour and weekly limits are gone. The API has rate-limit headers the loop doesn't read, and a spending cap is the player's to set in the console.
- **Updates.** Claude Code moves with the API by itself. The loop has an API version, model ids and prices in code, so a new model or price needs a game update, and a retired id stops it.
- **Permission modes.** `dontAsk` and the allow-list are Anthropic's code. Here they're ours, which is the list above, and only as good as that.
- **Compaction.** Each message is one short loop, so it isn't missed here. It would be for a chat that kept its history.
- **A tested client.** Claude Code has met far more failures than this has. The loop's first real call failed on a null it didn't expect.
- **F9, CLAUDE.md, the rest of the tools.** The terminal is Claude Code's alone. The loop doesn't read `Guide`, and nothing suffered.
- **Terms.** J-060 covers Claude Code only. Whether a game may run this loop on a player's key needs its own check. Not looked at here.

This counts prompts like these sets, and a player's own may run longer.

## Recommendation

1. **Keep the API path as a real adapter, for players without a Claude plan, and keep it off the default.** Claude Code on Haiku stays right for anyone with a plan: nothing per prompt, sign-in done, updates done.
2. **For this path, Haiku.** It's the faster and the far cheaper, and it passes everything here. Opus isn't faster through it.
3. **Before it ships:** key storage, the picker, J-060's check for this path, reading the rate-limit headers, and the words streaming into the box. The loop itself is nearly there: what's left in it is a real mid-stream cancel.
4. **Take the notes idea back to Claude Code now.** The game could put `notes.md` into the message on stdin, and drop the failed `Read`: about one reply a prompt. Not tried on Claude Code.
5. **Most of Haiku's gain isn't the API's,** so don't read this as Claude Code being slow. Part is notes, and part fewer tool calls: 4.2 against 6.6. What's only the API's is the 1.3 s to the first tool, and what's only the cache's is writing a quarter as much.

- A real cancel, or a real timeout.
- Claude Code on the same tree across all 8 of the fixed set: its "short" rows are from before the squirrel merge, on 2 runs. The rule and question weren't in the merged run.
- Any effort but the default, Sonnet, or a real player's prompts.
- The 5-minute prefix, and a cache gap over 7 minutes.
- A key with low limits, a spending cap reached, two peers, or the loop in a built player: it ran only in the Editor.
- `ApiWire` under Unity's IL2CPP or on a Mac. The Windows Editor only.
- What the dollars look like in the console: they're worked out from `usage`, and not checked against the bill.
- Whether a colour shows in the frames, as in the earlier docs.

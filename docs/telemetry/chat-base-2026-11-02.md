# Chat base run, 2026-11-02

The numbers before any tuning (#59 item 5, J-064): the fixed set in `chat-prompts.json` through the game's real chat to Andrew's
real signed-in Claude, three runs, nothing changed. Next to compare with: three runs after each change, one change at a time.

**Setup.** Commit: `chat-tune` off 6e46f1d (the records say 6e46f1d). Model `claude-opus-5-5`, chosen by nobody: the chat passes no `--model`,
so a player gets their account's default. claude 2.1.316, Max account (`apiKeySource: none`), `dontAsk`. Solo in a hidden batchmode Editor
(not a player) at about 65 fps, yard scene, room open, one player, each prompt on a fresh world with no notes unless it says otherwise.

**Spent.** 27 real prompts: 24 base, 3 debugging (one proof, two on the run that found the lost record). $4.22 at list price.
Weekly limit 63% before and 63% after. The five-hour window went from 10% to 17%, but other sessions share it.

**Run it.** `tools/probe.sh chatprompts` proves the probe on a stand-in and spends nothing. `tools/probe.sh chatprompts --real-claude true --out <folder>` spends
real prompts: at most 8 a run (a cap in the code), stopping at a sign-in failure or past 85% of the weekly limit, which each stream reports. Start the Editor with no `CLAUDE*` variables:
the probe refuses to spend from inside a Claude session. A run takes under 3 minutes. Then `node tools/chat-report.mjs <folder>` and `node tools/chat-check.mjs <folder>`.

## Where the time goes

- **The model is the time:** a median of 94% of each run. Starting up 3% (0.5 s, steady), tools 3%. The last tool's answer is never what the player is waiting for.
- **Nothing happens for about 2 s:** the first reply comes at a median of 2.1 s (1.3 to 2.3), on every prompt. That's the floor, and only a question gets near it.
- **The world changes 2.6 to 3.9 s before the end,** spent writing `notes.md` and the reply. The player has it by then; the bar still shows work.
- **The steps, not the size, set the time.** Fire is the slowest prompt, not the house: "all fire" is 9 `set_look` calls, as each of 7 spells has its own colours, with 10 or so `describe` calls before them. 54 `set_look` and 44 `describe` in the 24 prompts.
- **The game is fast.** The server took 13 ms a call at the median, waiting 8 ms of that for the main thread (worst 25), and the worst call was an `apply` at 263 ms. All 227 game calls took 10.3 s in 24 prompts: 8.3 s in the server, 2.0 s on Claude's side.
- **A switch costs one frame** of 85 to 125 ms; composing the rules takes 62 to 76 ms of it.

## Where the tokens go

- **Cached reads are 91.8% of the input side:** 2,758,553 read, 246,002 written, 266 plain, 37,118 out (5,542 of that thinking).
- **But writes are the money.** List price by kind: cache writes $1.97 (60%), output $0.74 (23%), cached reads $0.55 (17%). Every write is on the 1-hour tier, at twice the input price. Reads are 92% of the tokens and 17% of the cost.
- **What a prompt pays before it starts.** The first reply reads or writes about 16,530 tokens. From the first replies: 12,044 is the same for any folder on this account, 1,746 is the folder, and 2,740 or so is new with each message, so every prompt writes at least that. That's an inference from the counts: the stream doesn't show the prompt.
- **Cold and warm.** Nothing cached: 16,533 written (the proof, $0.405 for the blue prompt). New folder, same hour: 4,486 written. The same message in the same folder within the hour: none (run 1's first two prompts, by accident: a debugging run had used that folder, which is why they're the cheapest of theirs). Each reply then re-reads all of it, so cached reads grow with replies times context.
- **That base isn't a stranger's.** Andrew's Claude loads 68 skills, 4 plugins and 103 slash commands, and `--strict-mcp-config` stops none of those. A player with a bare install probably pays less: not measured. *Measured since, and wrong: they add nothing to a prompt (`chat-model-2026-11-02.md`).*
- **The cheapest a prompt can be** is the question: 2 replies, 33,445 tokens, $0.036.

## One bug fixed, as the numbers needed it

A prompt that fixes an earlier one lost its own record. `ChatTelemetry` wrote the record and the `afterwards` line on two threads at once, `File.AppendAllText` threw on the second, and the task swallowed it. The first real follow-up vanished this way, and so would any prompt in play that fixes the last one.
`ChatLog.Append` now takes a lock, with a test (`LinesWrittenAtOnceAllLand`) that fails without it. Nothing else in the recorder changed: every other wrong field above stands for its own pass.

Two guards also went in for anyone running real prompts: an Editor shares its data folder with the player's game, so the chat folder holds Andrew's real `notes.md`, and a sign-in failure would open a terminal on his screen. `ClaudeTerminal.TestFolder` moves the folder and stops that window, for this probe and the `chat` probe, which was rewriting his notes each run.

## What the numbers point at (no change made)

1. **Model choice is the first lever, and the chat doesn't make one.** At 94% of the time, only the model or the number of replies can move prompt to world. Chatbench's Haiku 5.5 did the same five prompts at about half the time and a hundredth of the list price, but with 7 tool calls for blue to Opus's 26: it was one run, on another machine, with no check that all 7 spells turned blue. The same set on Sonnet 5.5 and Haiku 5.5 will say, and it needs a stronger expected outcome for "all fire" first.
2. **Cache writes, not reads.** 8% of the input tokens are 60% of the price, all at the 1-hour rate. Each prompt writes 2,700 at least, and fire writes 20,000 or more, mostly what tools return. Smaller tool answers and fewer `describe`s cut writes and replies together. A 1-hour cache suits a player who pauses and comes back, so the tier isn't obviously wrong: on a plan what matters is the limit, and how limits count these tokens is unknown.
3. **Fewer steps for the common ask.** A way to set the fire look for every fire spell in one call would take most of 26 calls off the commonest kind of prompt. And Andrew's 68 skills are in the base, so what a bare player pays should be measured before tuning for it.
